## 当前状态

`use_type_reference=True`。这不改变 C++ 输出；默认模式下手改字段类型需要同步修改辅助类型。

默认渲染器兼容调用，后者及包级入口已另行通过定向测试。

同一基准随后加入真实生成的共享自引用图：根对象的两个句柄指向同一子对象，子对象再指向

严格解码仍比较指纹。针对文本和编译期字节分别编码得到相同完整头部，严格匹配与损坏拒绝的
测试通过，真实手改后的 Python/SV/C++ 往返也通过。

本地一次交替测量中，与仍使用旧文本转换的直接展开对照相比，8 元素对象的生成路径从约

8284 ns/次降至 8200 ns/次。共享循环图中直接对照仍采用旧头部转换时为 461 对 388 ns/次，
分配为 11 对 9 次。此对比同时包含头部转换差异，不能作为字段清单本身的性能结论。
将直接对照也改为使用编译期字节后，独立测得小对象生成/直接约 1.025、大容器约 0.999、
共享图约 0.992；分配次数分别为两侧各 3、3、9 次。这些只是当前编译器和环境的结果。
